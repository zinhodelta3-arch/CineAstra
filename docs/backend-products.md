# Insumos e equipamentos — tarefa 23

O módulo expõe `GET/POST /api/inputs`, `GET/PATCH/DELETE /api/inputs/:id` e as cinco operações equivalentes em `/api/equipment`. `GET` lista com `limit`, `cursor`, `localId`, `status` e, para ADMIN, `supplierId`. ADMIN consulta todos; FORNECEDOR consulta apenas os próprios itens. IDs são strings decimais e `preco` é string decimal exata. `DELETE` marca `INDISPONIVEL`, sem remover linhas referenciadas. PATCH não permite trocar fornecedor/local.

ADMIN gerencia autorização operacional em `GET/POST /api/admin/suppliers/:supplierId/locations` e `DELETE /api/admin/suppliers/:supplierId/locations/:localId`; FORNECEDOR consulta `GET /api/suppliers/me/locations`. A migration `20261008_08_supplier_products.sql` cria `fornecedor_locais` com FK para ambos e adiciona UNIQUE sobre patrimônio normalizado (trim/uppercase). Antes do ALTER, auditar duplicatas legadas de patrimônio. Vínculo ativo, conta FORNECEDOR ativa e local ATIVO são necessários para criar ou editar como fornecedor; ADMIN também precisa do vínculo na criação e para reativar item. A conta autenticada determina o fornecedor, sem aceitar outro `supplierId` do FORNECEDOR.

Criação inicia `quantidade = 0`; a API rejeita `quantidade` em POST/PATCH. O saldo muda somente por movimentos de estoque da tarefa 26. `quantidade_minima` é limiar de alerta, não saldo. `preco` de insumo é preço de catálogo e não custo de aquisição: não existe coluna `custo` no schema, por isso a API rejeita esse campo. Equipamento não tem preço/custo. Patrimônio opcional não nulo é único independentemente de espaços nas pontas e caixa; itens sem patrimônio podem coexistir.

As 14 operações constam em `backend/docs/openapi.json`. `backend/tests/product.test.js` cobre escopo, fornecedor alheio, preço, saldo, patrimônio e arquivamento. A suíte MySQL opt-in em `backend/tests/integration/identity.mysql.test.js` cobre FK/UNIQUE/HTTP em schema `_test` vazio. Nenhuma migration foi aplicada nesta rodada; sem `TEST_DB_*` e opt-in, a execução SQL real permanece pendente. RF25/RF26 continuam parciais até movimentos de estoque, consumo e integração operacional posteriores.
